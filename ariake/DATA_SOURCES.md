# 有明エリア混雑モニター：データソース一覧

「使える／使えない」を先に書いたうえで、実装済み・追加候補を並べています。
金額やAPI仕様は変わるので、導入前に各提供元の最新条件を確認してください。

---

## 0. 先に重要な注意：Google マップの「混雑する時間帯」について

| 事実 | 内容 |
|---|---|
| Places API には無い | Google の公式 API（Places API / Place Details）は **混雑する時間帯 (Popular Times) やリアルタイム混雑度を返しません**。有料プランでも提供されていません。 |
| スクレイピングは不可 | Google マップの画面から混雑バーを直接取得するのは Google の利用規約違反です。本プロジェクトでは行いません。 |
| 正規の代替 | Google 由来の人流指標をライセンス再配布している **BestTime.app** などの有料 API を使います（`sources/popular_times.py` で実装済み）。 |
| 別の代替 | Routes API の「渋滞込み所要時間 ÷ 平常時所要時間」を**道路混雑の代理指標**として使えます（`sources/routes.py` で実装済み）。 |

つまり「Google マップの混雑状況」は、**そのままでは取れない**のが前提です。
本サービスは代わりに「イベント来場者の到着／退場カーブ」を主エンジンにし、
取れるものは実測で補正する構成にしています。

## 1. 実装済みのデータソース

| # | ソース | 内容 | 費用 | 設定 |
|---|---|---|---|---|
| 1 | 各会場の公式イベントカレンダー | 東京ビッグサイト／有明アリーナ／東京ガーデンシアター／有明コロシアム／有明四季劇場／有明ガーデン／有明GYM-EX | 無料 | 不要（`config.EVENT_SOURCES`） |
| 2 | 気象庁 予報 JSON | 東京地方の天気・降水確率・気温（7日先まで） | 無料・キー不要 | 不要 |
| 3 | holidays-jp（内閣府公表データ由来） | 祝日カレンダー | 無料・キー不要 | 不要 |
| 4 | 公共交通オープンデータセンター (ODPT) | ゆりかもめ／りんかい線／JR京葉線／メトロ有楽町線の運行情報。都営バスのリアルタイム位置も取得可 | 無料（要登録） | `ODPT_TOKEN` |
| 5 | BestTime.app | Google の人気時間帯に相当する曜日×時刻カーブ＋ライブ混雑度 | 有料 | `BESTTIME_API_KEY` |
| 6 | Google Routes API | 渋滞込み所要時間 → 道路混雑スコア | 従量課金（無料枠あり） | `GOOGLE_MAPS_API_KEY` |
| 7 | `manual_events.json` | 手入力のイベント（スクレイパの取りこぼし対策） | 無料 | 任意 |

キー未設定のソースは自動でスキップされ、残りのソースだけで予測が動きます。

## 1-2. 月額コストの目安

呼び出し回数は実装から確定値が出せます（価格は各社の改定があるので要確認）。

| ソース | 月間リクエスト | 費用の目安 |
|---|---|---|
| 気象庁・holidays-jp・イベント取得 | — | **¥0** |
| ODPT | 約 2,880（4事業者×24回/日） | **¥0**（無料登録。商用利用は別途確認） |
| Google Routes API | 約 720（1ルート×24回/日） | **¥0**（無料枠内。5ルートに増やしても枠内） |
| BestTime.app | 約 4,800（下記内訳） | プラン次第。`monthly_credit_cap` で上限を固定 |
| GitHub Actions | 毎時 × 約1.5分 ＝ 約1,080分 | **¥0**（private の無料枠 2,000分/月に収まる） |

BestTime の内訳（`config.BESTTIME` の既定値）:

- ライブ混雑: 26施設 × 6回/日（11〜21時の2時間おき）× 30日 = **4,680**
- 平常カーブ: 26施設 × 週1回 = **104**

時間帯・間隔・対象施設を変えれば費用は線形に増減します。
同じ時間帯に2回走っても1回しか引かないガードがあるため、
Actions の実行間隔を変えても BestTime の費用は動きません。

BestTime の単価が分かれば、月額はそのまま掛け算で出ます:

| 1リクエストあたり | 月額（4,800リクエスト） |
|---|---|
| $0.01 | 約 $48（約 7,200円） |
| $0.02 | 約 $96（約 14,400円） |
| $0.03 | 約 $144（約 21,600円） |
| $0.05 | 約 $240（約 36,000円） |

実際には「月額プラン＋含まれるクレジット」の形が一般的なので、
5,000クレジット前後を含むプランを選べば足ります。

## 2. 追加候補（公的・無料）

精度を上げたいときに効く順に並べています。

1. **国土交通省 人流オープンデータ（G空間情報センター）**
   500m／1km メッシュの滞在人口を無料配布。有明エリアの「平常時の人出」を
   実データで較正でき、本サービスの baseline を事前分布から実測に置き換えられます。
   過去データなのでリアルタイムには使えませんが、**学習用として最も価値が高い**。
2. **JARTIC（日本道路交通情報センター）交通量オープンデータ**
   5分間交通量・旅行速度。湾岸道路・首都高有明周辺のリンクを拾えば、
   Routes API に課金せずに道路混雑を取れます。
3. **東京都オープンデータカタログサイト / 江東区オープンデータ**
   施設情報、人口、イベント、公共施設の利用状況など。
4. **東京都交通局・都営バスのリアルタイム位置情報（ODPT 経由）**
   バスの遅延は道路混雑の実測に近く、有明↔豊洲・東京駅の詰まりが見えます。
5. **各鉄道事業者の「混雑予想カレンダー」ページ**
   ゆりかもめ・りんかい線は大型イベント日に臨時ダイヤ／混雑予想を告知します。
   イベント検知の答え合わせに使えます。
6. **駅別乗降人員（JR東日本・東京メトロ・ゆりかもめの公表値）**
   年次データですが、駅ごとの `scale`（何人でスコア100か）の較正に使えます。
7. **気象庁アメダス実況（10分値）**
   予報ではなく実況。急な降雨で人出が動くのを即座に反映できます。
8. **東京臨海副都心エリア・有明ガーデン等の駐車場満空情報**
   駐車場の満車は来場ピークの**先行指標**として非常に強い。
   公開ページがある駐車場をスクレイプ対象に追加する価値があります。
9. **道路ライブカメラ（国交省・東京都）**
   画像から滞留を推定できますが、個人が映る可能性があるため
   画像の保存はせず、混雑度の数値化のみに留める運用が必要です。

## 4. 補助的・間接指標

- **X（旧Twitter）API**：「有明」「ビッグサイト」「ゆりかもめ」の投稿量。
  入場規制・退場規制の第一報が最速で出ます（API は有料）。
- **各会場の公式 X アカウント**：入場規制／退場規制の公式告知。
- **Google Trends（pytrends）**：イベント名の検索量 → 来場規模の先行推定。
- **チケットぴあ／イープラス／ローソンチケットの公演情報**：
  会場公式に載らない公演を補完でき、イベント網羅率が上がります。
- **Yahoo! MAP 混雑レーダー／Yahoo!乗換案内の混雑予報**：
  アプリ内機能で **API 提供なし**。参考閲覧用。
- **駅すぱあと／ジョルダン 運行情報 API**：有料。ODPT の冗長化用。

## 5. 精度を上げる手順（実装済みの仕組み）

1. `observations` テーブルに実測を貯め続ける
   → 3件以上貯まったマスから、平常値が事前分布の代わりに使われます。
2. `forecasts` テーブルに予測を毎回記録
   → 後から実測と突き合わせれば、誤差の大きい重みを特定できます。
3. 会場が公表する来場者実績で `EVENT_SCALE_KEYWORDS` の推定人数を較正。
4. `INFLUENCE`（会場→周辺スポットの波及率）を実測差分から調整。

---

## 6. スクレイピングの運用方針

- アクセス間隔は同一ホスト 1.2 秒以上（`util.HTTP_SLEEP`）。
- User-Agent に用途と連絡先リポジトリを明記。
- 取得は 30 分に1回まで。イベント情報は本来 1 日1回で十分。
- robots.txt と各サイトの利用規約に従う。取得不可の会場は
  `manual_events.json` で手入力する運用に切り替える。
